# API BlueProcure

Tài liệu cho người tích hợp hoặc phát triển tiếp. Mô tả đầy đủ kiểu dữ liệu (máy đọc được) nằm ở `/openapi/v1.json`, có giao diện thử tại `/docs` (Scalar). Bảng endpoint cuối tài liệu được **sinh từ chính mã nguồn** (route, quyền, kiểu dữ liệu, chú thích XML). Test `ApiDocTests` báo lỗi khi bảng cũ hơn mã. Để sinh lại, chạy `scripts/gen-api-doc.ps1` hoặc `scripts/gen-api-doc.sh`.

## Quy ước chung

| Mục | Quy ước |
|---|---|
| Địa chỉ | Cùng origin với web: `https://<máy chủ>/api/...` (nginx chuyển tiếp). Môi trường dev: web `:47080`, API `:47081`. |
| Định dạng | JSON UTF-8, tên thuộc tính camelCase; enum truyền **dạng chuỗi** (`"Effective"`, `"NonBidding"`). |
| Thời điểm | ISO 8601 có múi giờ, lưu và trả về theo UTC (`2026-10-17T03:15:00+00:00`). Giao diện tự đổi sang giờ Việt Nam. |
| Ngày | `yyyy-MM-dd` (kiểu `DateOnly`), hiểu theo lịch Việt Nam. |
| Tiền, số lượng | Số thập phân JSON (`1234567.5`), đơn vị VND; không có ký hiệu tiền. |
| Định danh | UUID v7, không có id tuần tự. |
| Mã tương quan | Gửi `X-Correlation-Id` (tùy chọn); máy chủ luôn trả lại header này và ghi nó vào mọi dòng log. |

### Xác thực

1. `POST /api/auth/login` `{ userName, password }` trả về `accessToken` (JWT, sống ngắn) và đặt cookie refresh (httpOnly, `SameSite=Strict`). Nếu tài khoản bật 2FA thì phản hồi có `requiresTwoFactor: true` và `twoFactorChallenge`; gọi tiếp `POST /api/auth/login/2fa` `{ challenge, code }` với mã TOTP.
2. Gửi `Authorization: Bearer <accessToken>` ở mọi yêu cầu.
3. Khi nhận `401`, gọi `POST /api/auth/refresh` (cookie tự gửi kèm). Cookie refresh đổi mới sau mỗi lần dùng, nên các lời gọi refresh đồng thời phải dùng chung một yêu cầu.
4. Đăng nhập bị giới hạn tần suất. Sau 5 lần sai liên tiếp, tài khoản bị khóa tạm thời.

Cột **Quyền** trong bảng cho biết điều kiện gọi:
- `Công khai`: không cần đăng nhập.
- `Đăng nhập`: mọi người dùng đã đăng nhập.
- Mã quyền: cần **một trong** các quyền liệt kê; quyền được gán theo vai trò ở trang Vai trò & phân quyền.

Ngoài quyền, dữ liệu còn lọc theo **phạm vi dữ liệu** của người dùng (cơ sở, khoa, mảng) và theo NCC đối với tài khoản nhà cung cấp. Bản ghi ngoài phạm vi trả về `404`, không trả `403`.

### Lỗi

Mọi lỗi trả về dạng [RFC 7807](https://www.rfc-editor.org/rfc/rfc7807) `application/problem+json`:

```json
{
  "status": 400,
  "title": "Số hợp đồng đã tồn tại.",
  "type": "https://blueprocure.local/errors/CONTRACT_NUMBER_EXISTS",
  "code": "CONTRACT_NUMBER_EXISTS",
  "correlationId": "01a1465c48c973a7ba21355157703479"
}
```

- `code` là mã ổn định để máy xử lý; `title` là câu tiếng Việt để hiển thị cho người dùng.
- Lỗi kiểm tra dữ liệu đầu vào trả thêm `errors: { "<Trường>": ["..."] }`.
- Ý nghĩa mã trạng thái:
  - `400`: dữ liệu hoặc quy tắc nghiệp vụ không thỏa.
  - `401`: chưa đăng nhập hoặc token hết hạn.
  - `403`: thiếu quyền.
  - `404`: không có, hoặc nằm ngoài phạm vi dữ liệu.
  - `409`: xung đột, ví dụ người khác vừa sửa cùng bản ghi hoặc trạng thái đã đổi.
  - `413`: tệp quá lớn.
  - `429`: vượt giới hạn tần suất.

### Danh sách, phân trang, xuất Excel

Mọi danh sách nhận các tham số query sau:

| Tham số | Ý nghĩa | Mặc định |
|---|---|---|
| `page` | Trang cần lấy | 1 |
| `pageSize` | Số dòng mỗi trang, tối đa 200 | 20 |
| `search` | Từ khóa tìm kiếm | |
| `sortBy` | Tên thuộc tính để sắp xếp; mỗi endpoint chỉ nhận một danh sách cho phép | |
| `sortDesc` | Sắp xếp giảm dần | `false` |

Ngoài ra mỗi endpoint có bộ lọc riêng, xem bảng bên dưới. Kết quả có dạng `PagedResult<T>`: `{ items, total, page, pageSize }`. Các endpoint `.../export` nhận cùng tham số và trả về tệp `.xlsx`, tối đa 10.000 dòng.

### Tệp

- **Tải lên**: `multipart/form-data`, trường `file`, tối đa 20 MB. Loại tệp được kiểm tra bằng nội dung (magic bytes), không dựa vào tên hay `Content-Type`. Tệp sai loại bị từ chối với mã `*_INVALID`.
- **Tải xuống**: API kiểm tra quyền trước rồi trả nội dung, hoặc trả một đường dẫn có chữ ký sống ngắn.

### Thời gian thực

SignalR hub `/hubs/notifications` (token qua `?access_token=`) đẩy sự kiện `notification` gồm `{ type, title, body, link }` khi có tài liệu chờ ký, bị trả lại, v.v. Client nên tải lại dữ liệu liên quan khi nhận sự kiện.

### Tích hợp HIS

Các endpoint `/api/integration/his/...` dành cho HIS: xác thực bằng API key + chữ ký HMAC-SHA256 (`X-Api-Key`, `X-Timestamp`, `X-Signature`), chống phát lại ±5 phút, có whitelist IP. Định dạng và ví dụ xem [HIS_INTEGRATION.md](HIS_INTEGRATION.md).
